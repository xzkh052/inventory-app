# 库存管理（Inventory App）

一个**纯本地、离线可用**的库存管理程序。零件 SKU 库 + 产品 BOM 库 + 出入库 + 最大套数测算 + 库存预警 + 出库计划。

- **Mac 本地**：双击 `启动.command` 即可用
- **iPhone**：Safari 打开后「添加到主屏幕」，变成 App，断网可用
- **数据**：全部保存在本设备浏览器本地（IndexedDB），**不上传任何服务器**
- **多设备**：每台设备数据独立，用「数据」页的导出/导入 JSON 手动备份或迁移

---

## 一、Mac 上怎么用

### 方式 A：双击启动（推荐）

1. 打开 `inventory-app` 文件夹
2. 双击 **`启动.command`**
3. 终端会显示网址 `http://localhost:8001`
4. 浏览器自动打开，即可使用

> **端口固定为 8001**，保证数据来源始终一致，不会出现"数据消失"。
> 首次双击若提示「无法打开，因为来自身份不明的开发者」，右键点 `启动.command` → 选「打开」→ 再点「打开」即可。

### 方式 B：手动启动

在终端里执行：

```bash
cd ~/Desktop/inventory-app
python3 -m http.server 8001
```

然后浏览器打开 `http://localhost:8001`。

> 为什么不能直接双击 `index.html`？因为浏览器对 `file://` 协议下的 Service Worker 和部分功能有限制。用本地服务最稳。

---

## 二、iPhone 上怎么用

1. 确保 iPhone 和 Mac 在**同一个 WiFi**
2. 在 Mac 上启动服务（见上），终端会显示本机 IP，例如 `http://192.168.1.5:8001`
3. iPhone 用 **Safari** 打开这个地址
4. 点底部「分享」按钮 → **添加到主屏幕**
5. 主屏幕会出现「库存」图标，点开即用

> 之后即使 Mac 关机、断网，iPhone 上的 App 依然能打开使用（数据在手机本地）。
> 但**首次加载**必须连上 Mac 的服务。

## 三、功能说明

### 1. 零件库
- 字段：SKU、零件编码、零件名称、采购单价、供应商、备注
- 自动显示每个零件的**当前库存**和**库存货值**
- 顶部统计：零件种类、在库总数量、**在库总货值**
- 编辑零件时可直接修改库存数（自动生成「盘点修正」流水）

### 2. 产品库
- 字段：产品名称、包含的零件及数量（BOM）、产品总重量（KG）、包装尺寸（CM）、备注
- 一个产品 = 若干零件的组合（支持同一零件填多个数量）

### 3. 出入库
- **入库**：按零件入库，类型可选「入库 + / 厂家赠送 + / 不良品补偿 +」
- **出库**：按产品出库，系统自动按 BOM 扣减每个零件；库存不足会**禁止出库并提示**
- **库存矫正**：按零件，类型可选「不良品 − / 正常损耗 − / 盘点修正（填实际库存）」

### 4. 最大套数测算
- 选择产品 → 自动显示**最大可组装套数** = min(各零件库存 ÷ 单套用量)
- 输入计划出库套数 → 显示每个零件的「当前库存 / 本次消耗 / 剩余」

### 5. 库存预警
- 每个产品可设：30天消耗量、补货天数、打包天数、海运天数
- 安全值 X = (30天消耗量 ÷ 30) × (补货 + 打包 + 海运)
- 库存 < X → **红色预警**；距 X 不足 10 天消耗量 → **橙色预警**

### 6. 出库计划
- 一条计划可包含**多款产品**，每款填各自数量
- 字段：预计出货日期、发货渠道、物流渠道名称、箱子数量、分成几票、运费单价（元/KG）、电商店铺、状态
- **运费预估** = 运费单价 × 总重量（总重量 = Σ 单件重量 × 数量）
- 可**导出 A4 排版的 PDF**（出库计划单）

### 7. 流水
- 所有出入库、矫正都记录成流水（只增不改）
- **库存 = 该零件所有流水之和**，永远可追溯

### 8. 数据
- 导出全部数据为 JSON 文件（备份 / 迁移）
- 导入 JSON（覆盖当前数据）
- 清空全部数据

## 四、上传到 GitHub

### 1. 创建仓库
1. 登录 [github.com](https://github.com)，点右上角 **+** → **New repository**
2. 仓库名填 `inventory-app`，选 **Public**（或 Private）
3. **不要**勾选 "Add a README file"
4. 点 **Create repository**

### 2. 上传文件
在终端执行（把 `你的用户名` 换成你的 GitHub 用户名）：

```bash
cd ~/Desktop/inventory-app
git init
git add .
git commit -m "库存管理程序初版"
git branch -M main
git remote add origin https://github.com/你的用户名/inventory-app.git
git push -u origin main
```

> 首次 push 会要求登录，按提示用 GitHub 账号或 Token 授权。

### 3. 开启 GitHub Pages（可选，让其他 Mac 直接访问）
1. 进入仓库 → **Settings** → 左侧 **Pages**
2. Source 选 **Deploy from a branch**
3. Branch 选 **main**，文件夹选 **/ (root)**，点 **Save**
4. 等 1~2 分钟，访问 `https://你的用户名.github.io/inventory-app/`

> 注意：GitHub Pages 是 HTTPS 的，Service Worker 能正常工作，iPhone 也能添加到主屏幕。
> 但**数据仍然存在每台设备本地**，各设备互不影响。

## 五、其他 Mac 怎么用

- **方式 1**：把整个 `inventory-app` 文件夹拷给对方，双击 `启动.command`
- **方式 2**：让对方访问你的 GitHub Pages 网址
- **方式 3**：对方 `git clone` 你的仓库到本地，再双击启动

## 六、数据备份建议

- 定期在「数据」页点 **导出全部数据**，保存 JSON 文件到 iCloud / 网盘
- 换电脑或手机时，用 **导入数据** 恢复
- **重要**：始终使用 `http://localhost:8001` 访问，不要换端口，否则会看到不同的数据来源

## 八、技术说明

- **纯前端**：HTML + 原生 JS + IndexedDB，无后端、无依赖、无构建
- **离线优先**：Service Worker 采用「网络优先」策略，有网拿最新代码，断网回退缓存
- **数据安全**：所有数据存在浏览器本地，不上传任何服务器
- **PWA**：支持添加到主屏幕，像原生 App 一样使用
